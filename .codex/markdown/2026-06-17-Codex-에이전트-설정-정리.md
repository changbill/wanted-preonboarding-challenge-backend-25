# Codex 에이전트 설정 정리

## 목적

이번 세션에서 Codex 하네스의 토큰 사용량과 중복 산출물을 줄이기 위해 에이전트 운영 규칙을 정리했다.

## 변경 요약

- phase 기준을 루트 `PLAN.md`의 단계로 고정했다.
- 계획은 루트 `PLAN.md`로 통합했다.
- phase 산출물은 `implementation.md`, `verification.md`만 남긴다.
- PR 산출물은 GitHub PR 본문으로 관리한다.
- `gh pr create --base master --head {branch}`로 PR을 직접 생성한다.
- 문서는 필요한 경우에만 읽고 수정한다.
- 검증은 기본 `.\gradlew.bat test` 하나만 실행한다.
- 서브 에이전트는 큰 조사나 리뷰가 필요할 때만 사용한다.
- 최종 보고는 변경, 검증, 커밋/PR만 짧게 남긴다.
- 진행 상태는 에이전트 내부 판단으로 처리한다.

## 현재 하네스 구조

```text
AGENTS.md
.agents/skills/codex-orchestrator/SKILL.md
.agents/harness/guard.ps1
.githooks/pre-commit
.codex/config.toml
_workspace/codex/{phase}/implementation.md
_workspace/codex/{phase}/verification.md
```

## 정리된 항목

- 상태 파일: `_workspace/codex/state.json`
- 상태 갱신 스크립트: `.agents/harness/set-state.ps1`
- phase 계획 산출물: `_workspace/codex/{phase}/plan.md`
- PR 초안 산출물: `_workspace/codex/{phase}/pr.md`
- 상태 조회 명령: `/status`
- 단계 상태 기록: `planning`, `implementing`, `verifying`, `committing`

## 문서 갱신 기준

- 코드 동작 정의 변경: `SPEC.md`
- 조사 또는 판단 변경: `RESEARCH.md`
- 실행 또는 입문 정보 변경: `README.md`
- 계획 체크 변경: `PLAN.md`

## 검증 결과

- `guard.ps1 -Command run -Phase "phase-02-PG adapter 선택 방식 개선" -Stage finish` 통과
- pre-commit hook 통과
- GitHub CLI PR 생성 확인
